## Mô tả

### Mục đích
Xây dựng logic phân đoạn (Segmentation) và phân trang (Pagination) văn bản động dựa trên cấu hình do người dùng chỉ định. Đảm bảo 1 segment không bao giờ bị cắt ở giữa chừng.

### Phạm vi
**Làm:**
- [ ] Viết hàm (ví dụ class `TextSegmenter`) nhận một danh sách các paragraph.
- [ ] Hàm phân đoạn hỗ trợ cấu hình qua tham số:
  - `split_on_enter` (bool): Tách đoạn khi gặp Hard Return (mỗi paragraph là 1 segment).
  - `split_on_soft_return` (bool): Tách đoạn khi gặp Soft Return (`\n` bên trong text).
  - `custom_markers` (list[str]): Tách đoạn khi gặp ký tự tùy chỉnh (VD: `【`, `※`).
  - `max_chars_per_page` (int): Giới hạn ký tự tối đa của một Page.
- [ ] Phân bổ các Segment vào các Page dựa trên giới hạn `max_chars_per_page`.
- [ ] Xử lý chính xác tổ hợp cấu hình theo logic:
  1. Chỉ Enter: Mỗi đoạn văn DOCX là 1 Segment.
  2. Chỉ Soft Return: Gặp `\n` là tách Segment.
  3. Chỉ Customize: Gặp marker bất kỳ đâu cũng tách Segment.
  4. Tổ hợp (Enter + Customize hoặc Soft Return + Customize): Chỉ tách Segment nếu sau Enter/Soft Return là ký tự Customize (được phép có khoảng trắng/tab ở đầu dòng). Các dòng bình thường không có ký tự Customize ở đầu sẽ bị gộp chung vào Segment hiện tại.

**KHÔNG làm:**
- Không code giao diện Setting ở task này (giao diện sẽ làm ở P1-CONF-002).

### Acceptance Criteria
- [ ] AC1: Logic nhận diện và tách đúng theo 4 kịch bản kết hợp tùy chọn ở trên.
- [ ] AC2: Bỏ qua thành công các khoảng trắng/tab ở đầu dòng khi xét kịch bản "Tổ hợp".
- [ ] AC3: Một segment không bị cắt ở giữa chừng khi phân trang. Nếu 1 segment quá lớn vượt quá page, nó vẫn phải đứng trọn vẹn trong 1 page.
- [ ] AC4: Đoạn văn đầu tiên của file luôn khởi tạo một Segment đầu tiên.
